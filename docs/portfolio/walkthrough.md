# Guided walkthrough (90–120 seconds)

Use only fictional sandbox data. Start from a reset demo and show the sandbox badge throughout.

| Time | Screen | Narration |
| --- | --- | --- |
| 0:00–0:12 | Owner workboard | “Northstar is a fictional home-services referral sandbox. Commissions follow verified work, with an audit trail from booking to refund.” |
| 0:12–0:28 | Programs | “An owner sets a program, assigns a partner code, and chooses a flat or percentage rule. Partner-specific rules take priority, then category rules, then the fallback.” |

| 1:16–1:33 | Owner claims | “The owner settles the claim in simulation, with a durable ledger entry and audit record.” |
| 1:33–1:48 | Refund and reports | “A refund adds a reversal and recovery record. The owner can explain the state and export exact minor-unit figures.” |
| 1:48–2:00 | Boundary notice | “This is a financial-workflow sandbox; real payouts, identity, tax, reconciliation, and compliance would be separate production work.” |

## Capture checklist

1. Run the local Docker Compose stack with preview SMS and Mailpit only.
2. Reset the sandbox and use a new fictional booking reference.
3. Capture owner and partner screens at 1280×720 or higher, with no browser secrets visible.
4. Trim dead time, add captions, and keep the sandbox and simulated-payment labels visible.
5. Review the final recording for fictional data before sharing.

# Security policy

## Scope

This project demonstrates financial workflow controls with fictional data and simulated payouts. It is not a production payment or identity system. The default SMS preview and Mailpit email modes are local test facilities. Real payouts, KYC, tax and regulatory work, production authentication, backups, monitoring, and provider operations remain separate projects.

## Reporting a vulnerability

Please report security issues privately through the repository's **Security** tab if private vulnerability reporting is available. If it is unavailable, contact the repository maintainer through a private channel before sharing details. Do not put exploitable steps, secrets, or personal data in a public issue. For non-sensitive defects, a normal GitHub issue is appropriate.

Include the affected version or commit, a minimal reproduction using fictional data, the expected and actual behavior, and potential impact. The maintainer will acknowledge a private report and coordinate a fix and disclosure when possible. No response-time guarantee or bug bounty is offered.

Never send real customer data, OTP codes, API keys, session secrets, or live provider credentials in a report.

## Supported versions

Security fixes target the current default branch. Historical commits and forks are not maintained.
